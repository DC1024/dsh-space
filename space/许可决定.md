# 许可决定：Apache-2.0 + 商标/用途两份说明，限制不写进许可证

时间：2026-10-23 晚（北京时间）  决定者：本空间 owner（唐怀瑟）  执行：桌面端 DSH 助手（lead）

## 决定

1. **许可证换成 Apache-2.0，去掉 AGPL-3.0-or-later。** 理由：AGPL 想解决的是"别人拿去做闭源服务"，代价是把每个使用者都变成潜在被许可人，插件生态也别扭；而 owner 真正要的"小鲸鱼不听别人指令"不是许可证能管的事。
2. **不设分层许可**（core Apache / SDK MIT / 文档 CC BY 这类方案一并作废）：一份 Apache-2.0 覆盖全部原创代码与文档。
3. **"只听主人"留在代码里，不留在许可证里**：入口（本机控制台 + owner 凭据 + CSRF）、任务信封（服务端生成、`external_content_can_authorize: false`）、自动审查、`AUTHORITY_RULES.md`（纯行为解释）。任何部署者零授权即得；改规则只需本地重签。
4. **删除"批准的仪式感"**：`data/authority-policy-v01.json` 从"owner 批准的授权清单"改为本地签收记录（`accepted_by: "local-deployment"`，只记录"这份规则在本部署被接受过"，不阻断、不代表批准）。`prepare_runtime.mjs` 的哈希校验失败不再中止启动，而是本地自动重签；只有作者自用时可设 `DSH_STRICT_AUTHORITY=1` 恢复严格校验。人格快照的 `persona_sha256` 改为可选：fork 不填就不校验。
5. **版权落款改为作者本人。** `LICENSE` 用 Apache-2.0 官方标准原文，末尾版权行按规范填 `Copyright 2026 唐怀瑟`；不再保留任何第三方项目的原文副本痕迹。`NOTICE` 同步署名。
6. **补 `TRADEMARK.md`（非许可条件）。** Apache-2.0 第 6 条本就不授予商标权，这份文件把它写清楚：名称「小鲸鱼 / 小鲸鱼专属空间」、鲸鱼形象、人设与作者署名归作者保留；改造版必须换名、换形象、显著标注"非官方、与作者无关"，不得暗示背书。它不改变 LICENSE 授予的代码权利。
7. **补 `使用条款.md`（非许可条件）。** 写明作者立场：用途是操作自己的设备；作者不参与、不协助未经同意操作他人设备、绕过他人鉴权、冒充身份这类用法；按现状提供、不担保、无官方托管服务、责任限制。开源后别人怎么用不管，作者不追踪不审查，与 LICENSE 冲突时以 LICENSE 为准。
8. **不改 Apache-2.0 条文本身**：第 6 条关于商标的表述保持官方原文，TRADEMARK.md 只是解释与执行，不是新增许可条款。

## 第二批决定（同日稍晚）：薄边界、完全权限、整包

9. **发布形态是整包**：整个仓库一个分发单元，不拆 SDK / 插件 / 子包。`workdir/li/release/public/` 是它的全量候选包（120 文件）。
10. **人格行为约束只留最薄一层**：入口（本机控制台 + owner 凭据 + CSRF）与任务信封（`external_content_can_authorize: false`）之外，不再往提示词里堆授权审查；`AUTHORITY_RULES.md` 从 v04 精简为 v05（约 2.2 KB），只说明"什么算指令"和"目标内自主执行"。
11. **自动审查档要很薄**：`REVIEW_POLICY` 改为默认放行、只看当前这一次调用的实际后果；输入只发 `ENVIRONMENT` + `PENDING_ACTION`（不再发历史与项目指令）；本地只读工具（read/glob/grep/todo_write 等）直接放行，不消耗审查模型调用；`maxTokens` 8192 → 1024。
12. **新增「完全权限」档**：`permission_preset` 写 `danger-full-access`（别名 `full`，`runtime-policy.mjs` 里映射）时，会话钉到内置零限制档，自动审查器（只审 `auto` 会话）对该会话不分类、不询问、不拦截——行为层面零限制。预算、暂停、设备互斥、观察门是运行时保护，不在此列。（本条"插件根本不挂载"的说法由第 15 条第一次更正，最终形态见第 20 条：本档确实不挂审查插件，改挂一个无钩子的 `auto` 身份空插件。）
13. **`使用条款.md` 软化**：从"禁止/违反条款"改为"作者不支持的用法 + 免责"，并写明作者不追踪、不审查别人拿去做什么。

## 第三批（同日更晚，独立审计后）：把口径落到实处

14. **启动默认值跟随档位**：`prepare_runtime.mjs` 不再固定写 `workspace-write + ask`。`danger-full-access`（含手写 `full`）组合出 `danger-full-access + never`；`read-only` 组合出 `read-only + ask`；`auto` 仍组合 `workspace-write + ask`（它不是可配置组合，随后由 `runtime-policy.mjs` 按会话钉到 `auto`）。认不出的值回退 `workspace-write + ask` 并打警告，不让错误档名卡住启动。
15. **完全权限的"不挂审查"如实说明**：审查插件在每个档位都会加载，因为 DSH 用持久化 `auto` 档恢复会话时若找不到提供 `auto` 的集成会直接报错；拆掉插件会让主人已有的表/里会话在下次重启时失效。完全权限下该插件不分类、不询问、不拦截（`runtime-auto-review.mjs` 对非 `auto` 会话在分类前就 `next()`），所以是零行为限制；文档改说"插件加载但对本档会话完全不生效"，不再写"根本不挂"。（第 20 条进一步改成条件挂载后，本条只保留历史记录。）
16. **`full` 别名在控制台也认**：`owner_settings.py` 新增 `PRESET_ALIAS` / `preset_id()`，读、显示、保存都先规范成 `danger-full-access`，不再出现"手写 `full` 能跑、控制台保存却报未知档位"。
17. **改档生效时点统一为"后续步骤"**：代码实际是每步重读配置，文档原先写"下一项任务生效"。改的是文档：立即对后续步骤生效，不撤销已提交目标，不改写已发生的事。
18. **发布清单按最终目录树重算**：`build_public.py` 原先在复制时记哈希、之后才定向改写，导致 `thinking_observer.py`、`integration/thinking-raw-mux.mjs` 两项哈希对不上，且生成的 README/.gitignore/许可文件不在清单里。改为全部复制与改写完成后枚举 `public/` 整棵树，逐文件记大小与 SHA-256（`schema: dsh-public-package-v2`），清单就是使用者收到的全部文件（当前 127 个）。
19. **`NOTICE` 与生成 README 的口径同步**：`NOTICE` 里的"用途限定/禁止"改为作者立场 + 不追踪不审查；生成 README 的四档说明补上"完全权限不分类、不询问、不拦截"与插件加载原因。

## 第四批（收尾，条件挂载）：把"完全权限"做成真的不挂审查

20. **审查插件改为条件挂载，完全权限不再挂审查插件**：`prepare_runtime.mjs` 按 `permission_preset` 决定插哪一行——`auto` 挂 `runtime-auto-review.mjs`（薄审查照旧），其它三档（`read-only` / `workspace-write` / `danger-full-access`）不挂审查插件，改挂新文件 `runtime-auto-preset-shim.mjs`。这个 shim 约 40 行，只做一件事：用 `permissionPresets.registerAuto()` 把 `auto` 这个名字继续提供给 DSH，保证主人早先存下的 `auto` 会话仍能恢复；它没有 pre-execute 钩子、不读工具调用、不询问、不写文件、不联网。于是完全权限档的会话路径上连审查钩子都不存在，而旧 `auto` 会话的恢复能力没有丢（只是恢复出来按当前档位钉，不再被审查）。
21. **改档位时重新生成启动补丁并标"待重启"**：`owner_settings.py` 保存 `permission_preset` 时不再只写 `config.json`，而是顺手重跑 `prepare_runtime.mjs` 生成新的启动补丁，成功后才落盘；失败则把配置和旧补丁一起回滚。同时写 `data/permission-pending.json`（`{preset, previous_preset, patch_sha256, saved_at, runtime_pid}`），控制台据此提示"档位已写进配置并重新生成补丁，请先暂停再重启运行时"。没有这次重生成，改档位在重启后不会换插件组合，嘴上说"完全权限零钩子"就是假的。
22. **文档口径同步**：`权限约束.md`、`LICENSE-SCOPE.md`、`AUTHORITY_RULES.md`、`安装与验证说明.md`、`build_public.py` 的 README 模板统一改成"审查插件只在 `auto` 档加载；其它档挂无钩子 shim，只为保住旧 `auto` 会话可恢复"。不改许可证、不增加条款。

## 界限

- 本决定取代此前任何"AGPL / 分层许可 / 需要作者授权 / 不加任何附加文件"的表述。此前"不加任何附加文件"那条作废：现在有 `TRADEMARK.md` 与 `使用条款.md` 两份说明，但它们**不是许可条件**，也不要求任何人向作者申请批准。
- 小鲸鱼（表/里）此前按 AGPL 写过根目录文档（2026-10-23 20:06 一批），已被本决定覆盖；如果后续再有文档写成 AGPL，以本文件为准。
- `workdir/li/release/public/` 的候选包需要同步这两份文件、LICENSE 版权行与 `public_manifest.json`（由她的打包脚本重建），本决定不代替那次重建。
- 未做的事：没有上传、没有发布、没有改任何第三方组件的许可；`assets/` 桌宠视频因许可未核实仍不打包。
